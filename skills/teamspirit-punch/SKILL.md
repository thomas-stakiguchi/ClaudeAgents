# TeamSpirit 打刻スキル

ユーザーがチャットで「勤務開始」「勤務終了」「打刻して」と言ったら、Salesforceコネクタを使って
TeamSpiritの **勤怠連携（teamspirit__ExternalAttendance__c）** に打刻レコードを1件作る。
TeamSpirit側がそのレコードを処理して勤怠日次に反映する。勤怠日次の時刻項目を直接書き換えてはいけない
（TeamSpiritの丸め・勤務体系判定・打刻ログを通らず、勤怠データとして信用できなくなる）。

使うツールは Salesforce MCP の `getUserInfo` / `soqlQuery` / `createSobjectRecord` の3つだけ。
SOQLの雛形と項目の意味は `references/teamspirit-objects.md` にまとめてある。

## ガードレール（先に読む）

1. **自分の勤怠社員以外は扱わない。** 打刻するのはコネクタでログインしている本人の分だけ。
   「〇〇さんの出勤を打刻して」「代わりに押して」と頼まれたら、理由を一言添えて断る。
   なりすまし打刻は労務上の不正になるので、頼まれても例外を作らない。
   `getUserInfo` には上司（manager）のユーザーIDも入って返ってくるが、使うのは `identity.userId` だけ。
   他人の勤怠社員や打刻状況を調べる必要もない（断るのに情報はいらない）。
2. **打刻時刻は「今」だけ。** 「9時で打刻して」「昨日の退勤を入れて」のような時刻指定・過去日付は受け付けない。
   打刻は事実の時刻を記録するものなので、修正はTeamSpiritの勤務表から本人が申請する流れに案内する。
3. **開始がないのに終了しない。** 当日の出社打刻がない状態で退社は打たない。
4. **同じ種別を1日に2回打たない。** すでに出社済みなら出社を、退社済みなら退社を打たない。
5. **迷ったら打たずに聞く。** 判定表で「確認」になったケースは、状況を説明して本人に選ばせる。
   打刻は取り消しに手間がかかるので、推測で押すより一往復増える方が安い。
6. **ドライラン対応。** 「テストで」「ドライラン」「確認だけ」と言われたら、レコード作成以外の全手順を行い、
   作成するはずだった内容を見せて終わる。

## 手順

### 0. 現在時刻を取る

`getUserInfo` を呼ぶ。返ってくる `userTimeAndLocale.localTimeIso`（UTC）と `timeZoneIana`（通常 Asia/Tokyo）を使い、
**日本時間の今日の日付** と **現在時刻（時:分）** を決める。自分の感覚や会話の文脈から時刻を推測しない。
同じ応答に `identity.userId` が入っているので、これが次の手順のログインユーザーIDになる。

### 1. 本人の勤怠社員を特定する

```sql
SELECT Id, Name, teamspirit__EmpCode__c, teamspirit__EntryDate__c, teamspirit__EndDate__c
FROM teamspirit__AtkEmp__c
WHERE teamspirit__UserId__c = '<identity.userId>'
```

| 結果 | 対応 |
|---|---|
| 1件、退社日が空か今日以降 | 進む |
| 0件 | 打刻しない。「TeamSpiritに勤怠社員の登録がないため打刻できません。管理者に確認してください」 |
| 2件以上 | 打刻しない。「勤怠社員が複数ひもづいています。管理者に確認してください」 |
| 退社日が今日より前 | 打刻しない。「退社日を過ぎている社員のため打刻できません」 |

ここで見つかった勤怠社員のIDと社員コード以外を、以降の処理で使ってはいけない。

### 2. 今日の打刻状況を調べる

2つ並行で問い合わせる。

**勤怠日次（反映済みの打刻）**

```sql
SELECT Id, teamspirit__Date__c,
       teamspirit__PushStartTime__c, teamspirit__PushEndTime__c,
       teamspirit__StartTime__c, teamspirit__EndTime__c,
       teamspirit__PushStartTimeHHMM__c, teamspirit__PushEndTimeHHMM__c
FROM teamspirit__AtkEmpDay__c
WHERE teamspirit__EmpMonthId__r.teamspirit__EmpId__c = '<勤怠社員Id>'
  AND teamspirit__Date__c = TODAY
```

**勤怠連携（投入済みでまだ反映前の打刻）**

```sql
SELECT Id, teamspirit__StampType__c, teamspirit__StampedDate__c, teamspirit__Status__c, teamspirit__Error__c
FROM teamspirit__ExternalAttendance__c
WHERE teamspirit__EmpId__c = '<勤怠社員Id>'
  AND teamspirit__StampedDate__c = TODAY
  AND teamspirit__Status__c IN ('未処理', '処理済み')
```

判定に使う値は次のとおり。

- **出社済み** = 勤怠日次の `PushStartTime__c` か `StartTime__c` に値がある、または勤怠連携に出社の未処理/処理済みレコードがある
- **退社済み** = 勤怠日次の `PushEndTime__c` に値がある、または勤怠連携に退社の未処理/処理済みレコードがある

`EndTime__c` は退社の判定に使わない。退社前でもシフトの終業時刻などが入っていることがある。
勤怠日次のレコードが無い場合は「出社も退社もしていない」と扱う。

時刻項目は 0:00 からの分数（例: 474 = 7:54）。表示には `...HHMM__c` の文字列を使うと楽。

### 3. 出社か退社かを決める

ユーザーの言葉と当日の状況を組み合わせて判定する。

| ユーザーの言葉 | 出社済み | 退社済み | 判定 |
|---|---|---|---|
| 勤務開始 / 出勤 / 開始 | なし | なし | **出社を打つ** |
| 勤務開始 / 出勤 / 開始 | あり | なし | 打たない。「今日は HH:MM に出社済みです」 |
| 勤務開始 / 出勤 / 開始 | あり | あり | 打たない。「今日は出社・退社とも済んでいます」 |
| 勤務終了 / 退勤 / 終了 | あり | なし | **退社を打つ** |
| 勤務終了 / 退勤 / 終了 | なし | なし | 打たない。「今日の出社打刻がないため退社を打てません。出社漏れであれば勤務表から修正申請してください」 |
| 勤務終了 / 退勤 / 終了 | あり | あり | 打たない。「今日は HH:MM に退社済みです」 |
| 打刻して（種別なし） | あり | なし | **退社を打つ** |
| 打刻して（種別なし） | なし | なし、現在 12:00 より前 | **出社を打つ** |
| 打刻して（種別なし） | なし | なし、現在 12:00 以降 | **確認する**。「出社打刻がありませんが、今から出社で打ちますか？（出社漏れなら勤務表から修正を）」 |
| 打刻して（種別なし） | あり | あり | 打たない。「今日は出社・退社とも済んでいます」 |

12:00 という境目は「午後に出社打刻がないのは打ち忘れの可能性が高い」という理由で置いている。
午後から出勤する人が「打刻して」とだけ言った場合も一往復増えるだけなので、この境目は保守的に守る。

「勤務開始」と種別を明示された場合は、午後でも出社を打つ（午後出勤は普通にある）。
ただし 12:00 以降なら「朝の打ち忘れなら、今打つより勤務表からの修正申請の方が実態に合う」と一言添える。
打った後に気づくより、打つ前に選べる方が本人にとって楽だから。

「確認する」になったケースでドライランを頼まれている時は、確認の質問に加えて
「出社で打つと答えた場合に作る内容」も見せる。ドライランの目的は動きを確かめることなので、
質問だけで終わると何が起きるか分からない。

### 4. 勤怠連携レコードを作る

ドライランならここで止め、作る予定だった項目を見せる。

`createSobjectRecord` で `teamspirit__ExternalAttendance__c` を1件作る。

| 項目 | 値 |
|---|---|
| teamspirit__EmpId__c | 手順1の勤怠社員Id |
| teamspirit__EmpCode__c | 手順1の社員コード |
| teamspirit__StampType__c | 出社 `1` / 退社 `2`（下の「要確認」を参照） |
| teamspirit__StampedDate__c | 手順0の現在時刻（UTCのISO 8601、例 `2026-09-10T00:02:15Z`） |
| teamspirit__InputDevice__c | `Claude` |
| teamspirit__UniqueKey__c | `claude:<社員コード>:<YYYYMMDD>:<start または end>` |
| teamspirit__AccessInfo__c | `Claude skill teamspirit-punch` |

ステータスは既定値（未処理）のままにする。外部キーを日付と種別で固定しているのは、
同じ日に同じ種別を二重投入した時に人が見て気づけるようにするため。

### 5. 結果を確かめて返す

作成したIdで1回読み直す。

```sql
SELECT Id, Name, teamspirit__Status__c, teamspirit__Error__c, teamspirit__StampedDate__c
FROM teamspirit__ExternalAttendance__c WHERE Id = '<作成したId>'
```

- ステータスが「処理済み」→ 打刻完了
- 「未処理」→ 投入は完了、TeamSpirit側の処理待ち。そのまま伝える
- 「エラー」→ エラー内容をそのまま見せ、TeamSpiritの勤務表から手動で打刻するよう案内する

## 応答の形

短く、事実だけ。

```
出社で打刻しました（09:02、勤怠連携 No.0000000012）。
```

```
今日は 08:41 に出社済みなので、出社打刻はしていません。退社なら「勤務終了」と言ってください。
```

```
【ドライラン】出社として打刻する内容です。実際には作成していません。
- 勤怠社員: 瀧口 翔史（0028）
- 打刻日時: 2026-09-10 09:02 JST
- 打刻種別: 1（出社）
```

```
退社打刻はしていません。今日の出社打刻が見つからないためです（勤怠日次・勤怠連携とも当日分なし）。
朝の打ち忘れであれば、TeamSpiritの勤務表から修正申請してください。
```

```
星野さんの分は打刻できません。このスキルはログインしている本人の打刻だけを扱います。
ご本人に勤務表から打刻または修正申請をしてもらってください。
ご自身の勤務開始は次の内容で打刻します。
```

## 要確認（本番で使う前に管理者が確認すること）

このスキルは組織の設定と項目名を実際に確認して書いているが、次の2点はTeamSpiritの仕様書かサポートでの確認が必要。
確認が取れるまではドライランでの利用にとどめる。

1. **打刻種別コードの意味。** 勤怠連携の打刻種別は `1 / 2 / 21 / 22 / 31 / 32` の6値。
   このスキルは 1=出社、2=退社 と仮定している（21/22 が休憩、31/32 が外出の開始・終了と思われる）。
   違っていたら手順4の値を差し替える。
2. **処理が動く設定になっているか。** 勤怠共通設定「IC勤怠連携機能を利用する」が現在オフ。
   オフのままだと投入したレコードは「未処理」のまま残る（2024年6月の投入7件がこの状態）。
   Sandboxでオンにして、投入したレコードが「処理済み」になり勤怠日次に反映されることを確認する。

あわせて、Salesforce側に「勤怠連携の作成者と勤怠社員のユーザーが一致しないとエラー」という入力規則かトリガーを
置くことを勧める。スキルのガードレールだけでは、権限を持つ人が他人の分を投入することを技術的には防げない。
