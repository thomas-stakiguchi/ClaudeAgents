## できていること

- 計画 → 承認 → ドライラン → 最終承認 → 入力データ取り込み → 登録 → 初回の1件だけ実行して停止 → 確認 → 残りを実行、という流れが、画面とコマンドで動きます
- 接続先は、スタブ（偽の画面）だけです。本物のChromeでも、スタブの画面に対して動きます
- 取り消せない操作は、1か所（12-1の関数）だけを通ります。承認、ドライラン、行の値、読み返し、状態、停止の旗を、関数の中で確かめます
- 同じ業務キーの二重実行を防ぎます。判定は、AIが振る手順IDではなく、エンジンが「接続先・操作・対象」から計算した識別子で行います
- 未解消の「処理中」「要確認」がある間は、本番を始めません
- 記録は追記のみで、実行の前にチェーンを検証します。ファイルは、所有者だけが読み書きできます
- 緊急停止、キルスイッチ、異常終了のあとの回復があります（緊急停止は Linux のみ）
