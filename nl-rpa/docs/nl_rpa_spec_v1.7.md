# 自然言語RPA 仕様書（v1.7）

## 1. 目的
- 業務の操作手順を、日本語で書くだけでRPAとして動かせるようにする
- 対象システムは限定しない（Webサイト、業務アプリ、ターミナル画面、ファイル、API など）
- 手作業の工数削減と、入力ミスの防止
- 取り消せない操作（発注、送信、削除など）で「間違えて実行しない」ことを、速さより優先する

## 2. 用語
| 用語 | 意味 |
|---|---|
| シナリオ | 担当者が日本語で書いた、操作の説明 |
| 画面の記録 | 人が対象の画面を開き、操作する要素に名前を付けて記録したもの（要素ピッカーで作る）。実行計画は、この要素名を参照する |
| 実行計画 | シナリオから作られる、機械が実行できる手順のデータ（構造化データ）。実行の正本 |
| 版 | 実行計画の更新履歴の単位。承認は版ごと |
| 手順ID | 手順に付ける、版をまたいで変わらない識別子 |
| 取り消せない操作 | システム上で元に戻せない操作（登録、送信、削除、購入、支払いなど）。業務上のキャンセル手続きがあっても、システム上で元に戻せなければ「取り消せない」に含める |
| 取り消せる操作 | 「操作許可リスト」にある操作だけ。業務データを変えないことが条件（ログインの最終ログイン時刻の更新のような、業務に影響しない記録は含む） |
| 操作許可リスト | 接続先の種類ごとに決める、「取り消せる操作」の一覧。ここにない操作は、すべて取り消せない扱い |
| 接続先許可リスト | 実行エンジンが接続してよい、ドメイン・ホストの一覧 |
| 確認条件 | 操作の結果を、機械で判定できる形で書いた条件（画面の文字、メッセージ、値など） |
| 業務キー | 業務上、1件の発注・処理を一意に決める値（例：発注元の伝票番号）。入力データの列で指定する |
| 実行エンジン | 実行計画を実行するプログラム。AIとは別物 |
| ドライラン | 取り消せない操作を実行せずに、手順の流れを確かめる実行 |
| 保管庫 | 認証情報を保存する場所。閲覧できる人を限定し、実行エンジンだけが読む |
| 実行用プロファイル | 実行ごとに作り、終了時に破棄する、専用のブラウザのプロファイル |
| 計画ハッシュ | **実行エンジンが計算**する値。正規化した実行計画（plan_hashの欄は除く）、操作許可リストの中身、接続先許可リストの中身、個別登録（7-1-1）の中身、画面の記録の中身から計算する。版番号ではなく、中身から計算する。承認とドライランは、この値に結び付ける（正規化とハッシュの方式は未定。実装前に決める） |
| 本番実行 | ドライランではない実行（取り消せない操作を実際に実行する）。接続先がテスト環境の場合も、本番実行と呼ぶ。スタブ相手の実行は、本番実行に含めない（ドライラン扱い。9-2） |
| 本番の接続先 | 業務で使う、本物の環境 |
| テスト用の公開サイト | 社外の公開サイトのうち、検索などの読み取りだけの用途で、試験のために接続してよいと定めたもの（14-7）。本番の接続先ではない |

## 3. 基本の考え方

### 3-1. 「書く → 確認する → 実行する」の3段階
1. **書く**：担当者が、日本語でシナリオを書き、対象の画面を記録する
2. **確認する**：AIがシナリオを実行計画に変換して見せる。人が確認して承認する
3. **実行する**：実行エンジンが、承認された版を、書かれたとおりに実行する

### 3-2. 実行中にAIは判断しない
- 実行エンジンは、承認済みの版だけを実行する（毎回AIが考え直して操作することはしない）
- 想定外のことが起きたら止まる。AIは「原因の候補」と「修正案」を出すだけで、適用は人が承認した新しい版として行う
- 実行計画に書かれていない分岐は、すべて「停止」
- AIが作る実行計画は、実行エンジンが形式をチェックしてから受け入れる。形式に合わないものは受け入れない

### 3-3. AIに渡す情報と、触れられる範囲
| 場面 | AIに渡す | AIに渡さない |
|---|---|---|
| 実行計画の作成 | シナリオの文章、入力データの列名、画面の記録の要素名と種類 | 入力データの値、認証情報、画面の中身 |
| 異常時の原因調査 | 停止時の画面の写し（マスク済み）、ログ | 認証情報、入力データの値 |
| 画面変更時の修正案 | 画面の写し（マスク済み）、現在の実行計画 | 同上 |

- AIは、対象システムに直接触れない（操作も、調査のための画面表示もしない）。写しやログだけを受け取る
- 対象の指定（どの要素か）は、AIが作らない。人が作った「画面の記録」の要素名を、AIが参照する
- データの値は、実行エンジンが実行計画に差し込む（AIを通さない）
- 画面の写しは、AIに渡す前に実行エンジンがマスクする（認証情報、列の型で「個人情報」と指定された値、入力データの値と一致する文字列を伏せる）。マスクの効果は未検証のため、人が結果を確認してから送る（SEC-7）
- AIの出力は、信頼しない入力として扱う。シナリオ・画面の写し・入力データの中に、仕組みのルールを変える指示（判定を外す、承認を飛ばす、外部へ送る、など）があっても、安全は、実行エンジンの決定的な検査（R4、R14、許可リスト、12-1）だけで守る。AIが指示に従わないことには頼らない（SEC-7）
- 他人が作ったシナリオを複製した場合は、再確認の対象にする
- 実行エンジンが接続できる先は、接続先許可リストで制限する

### 3-4. 対象システムの違いは「接続先の種類」で吸収する
| 接続先の種類 | 例 | 段階 |
|---|---|---|
| ブラウザ | 社内Webシステム、Webサイト | 第1段階 |
| 入力データ（読み込み） | CSV | 第1段階 |
| API、ファイルへの書き込み | REST API、共有フォルダ | 第2段階 |
| ターミナル画面 | 5250（AS/400）、3270、SSH | 第3段階（部品の有無は要調査） |
| デスクトップアプリ | Windowsアプリ | 将来 |

- 接続先の種類ごとに、操作許可リスト、ドライランの範囲、確認条件の書き方などを定義する（7章）
- 未対応の接続先は、その旨を表示して実行しない
- 画面を使わない方式（API・ファイル）が使えるなら、そちらを優先する（一般に安定しやすいとされるが、未検証）

## 4. 対象範囲
**やること**
- 自然言語でのシナリオ作成と、実行計画への変換
- 実行計画の確認、承認、ドライラン、実行
- 入力データ（CSVなど）を使った繰り返し実行
- 結果・ログの記録、停止・再開
- 画面や手順が変わったときの、修正案の提示（適用は人が承認）

**やらないこと**
- 業務内容そのものの正しさの判断（ただし、件数・数量・金額の上限チェックと、人の承認は行う）
- 実行中のAIによる手順の変更
- CAPTCHAの突破、他人の認証情報の利用
- 複数人での同時編集（初期段階）

## 5. 利用者の流れ
1. 対象の画面を記録する（要素に名前を付ける）
2. シナリオを書く（または既存シナリオを複製）
3. 入力データ（CSVなど）を選ぶ（任意）。業務キーの列を指定する
4. 「実行計画を作る」を押す。AIが不明点を質問するので答える
5. 実行計画を確認する
   - 各手順に、根拠となったシナリオの文が表示される。日本語の修正指示で変えた手順は「修正指示による」と表示
   - 根拠のない手順や値は「AIが補った」と表示される。取り消せない手順にAIが補った値がある場合は、その値を1つずつ確認しないと承認できない
6. **計画の承認**（ドライランに進むための承認）
7. ドライラン。結果（各手順の確認条件の合否）を確認する
8. **最終承認**（ドライランの結果を見たうえでの承認）
   - 第1段階はテスト環境のみのため、作成者が承認してよい
   - **本番の接続先で取り消せない操作を含む版は、作成者とは別の人の最終承認が必須**（SEC-1。確定）
9. 本番実行
   - 実行前に、件数・数量・金額のプレビューを見て、**件数を入力**して確認する
   - **初回は1件だけ実行して止まり**、人が結果を確認してから、残りを実行する
10. 結果を確認する。「要確認」があれば、人が判定を記入する

### 5-1. シナリオの例
> 発注管理システムにログインする。
> 入力データの各行について、発注画面を開き、商品コード・数量・納品日を入力する。
> 登録する前に、入力した値が元データと同じか確認する。
> 登録ボタンを押して、表示された発注番号を結果に記録する。

## 6. 機能要件
| No | 機能 | 内容 | 段階 |
|---|---|---|---|
| R1 | シナリオ作成 | 日本語で入力・保存・複製。複製したシナリオは、再確認が必要な印を付ける | 1 |
| R2 | 実行計画の作成 | シナリオを実行計画（付録A）に変換。不明点は質問する。答えが得られない箇所は「未確定」として残し、実行できない。各手順にシナリオの根拠の文を紐付け、紐付けのない値・操作は「AIが補った」と表示。作成に使ったモデル名・版・プロンプトの版を記録 | 1 |
| R3 | 実行計画の確認と修正 | 一覧表示。日本語での修正指示。変更点の差分表示。シナリオを変えたら計画を作り直し、承認済みの版との差分を表示。承認画面の主な説明は、実行エンジンが計画から機械的に作る（操作、要素名、値、取り消し可否）。AIが作る日本語の説明は、参考として併記 | 1 |
| R4 | 取り消せない操作の判定 | 9-1のとおり。**実行エンジンが操作許可リストから計算**する（AIの出力は使わない）。印は外せない | 1 |
| R5 | 承認 | 5章の2段階。版ごとに承認し、承認者・時刻を記録。版には、判定に使った操作許可リストと接続先許可リストの版を記録する。許可リストが変わったら、再判定と再承認が必要。承認は、計画ハッシュに結び付ける（SEC-2）。本番の接続先では、別の人の最終承認が必須（SEC-1） | 1（本番の別承認は2） |
| R6 | ドライラン | 9-2のとおり | 1 |
| R7 | 本番実行 | 実行前のプレビューと件数の再入力。初回は1件で止まる。取り消せない操作の直前に、読み返し照合（9-3） | 1 |
| R8 | 入力データ | CSVなどを読み込み、列定義（付録A-4）に照らして検査。業務キー列は必須。制御文字（改行、タブ）を含む値は不正。1件でも不正なら全件中止（不正行の一覧を表示） | 1 |
| R9 | 実行前の上限 | 取り消せない操作を含む版は、件数の上限が必須。数量・金額は、列の型で人が「数量」「金額」と指定した列に、上限を設定できる。単位は、実行ごと（第1段階）、1日ごと・接続先ごと（第2段階。実行をまたぐ累計の記録が必要）。超えたら中止 | 1（実行ごと）／2 |
| R10 | 二重実行の防止 | 9-4のとおり | 1 |
| R11 | 結果の記録 | 「行 × 取り消せない手順」の単位で状態を記録（10章）。累積で保存 | 1 |
| R12 | 停止・再開 | 通常の停止：実行中の手順が終わった時点で止まる。**緊急停止**：コンソールの専用コマンドで、記録したプロセスIDのワーカーとChromeをまとめて終了する。画面の停止ボタンは、停止フラグを立てる「通常の停止」（協調停止）で、緊急停止ではない。止めた時点で取り消せない手順の途中だった場合は、「要確認」にする。再開の条件は10章 | 1 |
| R13 | 異常時の支援 | 停止の原因候補と、修正案をAIが提示（3-3の範囲の情報のみ） | 2 |
| R14 | 修正案の扱い | 修正案はすべて新しい版。取り消せない操作の再判定、差分の表示、再承認、ドライランのやり直しが必須。次の修正案は**受け付けない**（実行エンジンが旧版との差分から機械的に判定）：①取り消せない操作の追加・変更②操作許可リスト・接続先許可リストの外の操作③確認条件の種類・値の変更、削除、緩和④エラーや警告の判定の削除、ダイアログを閉じて続行する処理の追加⑤手順の対象の要素名の変更、操作の種類の変更。受け付けない場合は、人がシナリオから作り直す | 2 |
| R15 | ログ | 操作・承認・AIの提案を時刻付きで保存。パスワードは出さない。入力値は、列ごとのマスク設定に従う（個人情報の列は伏せる）。記録項目はSEC-13、保護はSEC-9 | 1 |
| R16 | 通知 | 完了・停止・「要確認」の発生時に通知（手段、宛先は運用担当者と決定）。第1段階は画面表示のみ | 1（画面）／2 |
| R17 | 認証情報の管理 | SEC-4のとおり（保管庫、接続先ごとの結び付け、専用のlogin操作、AIには渡さない） | 1 |
| R18 | 接続先の確認 | 実行開始時に、接続先が設定どおりか確認（本番とテストの取り違え防止） | 1 |
| R19 | 権限 | 作成者・承認者・実行者を分けられる。接続先ごとの利用権限 | 2 |
| R20 | 待ちと再試行 | 各手順の待ち時間の上限（超えたら停止）。ログインの失敗は1回で停止し、再試行しない（アカウントロック防止） | 1 |
| R21 | 画面の記録 | 人が対象の画面を開き、要素に名前を付けて記録する（要素ピッカー）。画面が変わったときの再記録 | 1 |
| R22 | 許可リスト・個別登録の管理 | ルール管理者が、操作許可リスト、接続先許可リスト、個別登録（ボタン、URLパターン、パスワード欄、自動保存なしの画面）を管理する。変更は、承認と記録を伴う（SEC-1、SEC-13、7-1-1） | 1 |

### 6-1. 第1段階の範囲
- 第1段階を2つに分ける
  - **1a：スタブのみ**。接続先は偽の画面だけ。ブラウザ部品は、Chromeを使わない偽の部品とする（Chromeの実機を使うのは1b）。ダミーのシナリオだけを使い、機密を含めない。AIの送信先が未確定でも進められる
  - **1b：テスト環境に接続**。次が確定し、動作確認済みであること：SEC-6のネットワーク制限、SEC-2の記録の保存先の決定（LOC-8の限界を画面に表示）、SEC-7（AIの送信先・契約・保持）、保管庫の方式、実行する場所、14-6の追加条件のすべて
- 1aの最初の作業は、14-6のとおり（計画ハッシュの方式、付録Aの確定など）。1aのAIはスタブ（固定の実行計画を返す）とする
- 含む：段階が「1」の要件すべて、13章のSEC要件のうち段階が「1」のもの
- 含まない：R13、R14、R19、R9の1日ごと・接続先ごとの上限、R16の画面表示以外、第2段階以降の接続先

## 7. 接続先ごとの定義（接続先を追加するたびに作る）
各接続先の種類で、次の項目を定義する。定義がない接続先は、実行できない。

| 定義する項目 | 内容 |
|---|---|
| 操作許可リスト | 取り消せる操作の一覧 |
| ドライランの範囲 | どこまで実行するか、各行の終わりに画面を初期状態へ戻す手段 |
| 確認条件の書き方 | その接続先で、機械で判定できる条件の書式 |
| 画面を元に戻す手段 | 読み返し照合が不一致のときの戻し方 |
| 副作用の注意点 | 自動保存、途中の更新、アカウントロック、メール送信や外部連携（テスト環境でも動くことがある）など |

### 7-1. ブラウザ
- 既定は「読み取りのみ」が取り消せる
- 取り消せる操作として許可するもの
  - 画面の読み取り（文字、値の取得）
  - リンクの遷移：**遷移先URLのパターンを個別に登録したものだけ**
  - 入力欄への入力：「自動保存なし」と登録された画面の要素だけ
  - ボタンのクリック：副作用がないことを確認し、ルール管理者が個別に登録したものだけ（例：検索ボタン）。登録のルールは7-1-1
- 次は、取り消せない扱い
  - 個別に登録されていないボタンのクリック（確認ダイアログのOKを含む）
  - Enterキーによる送信
  - 自動保存のある画面での入力
  - 上記以外のすべて
- 確定操作が連続する場合（ボタン → 確認ダイアログのOK）は、**最初のボタンの操作から**取り消せない扱い。「処理中」は、そのボタンの直前に書く
- 画面を元に戻す手段：入力をクリアし、開始画面へ戻る
- 各行の終わりに、開始画面へ戻る
- 実行用プロファイル（SEC-3）、接続先の強制（SEC-5）に従う
- ダウンロード、ファイル選択、印刷、カメラなどの権限のダイアログが出たら、停止

### 7-1-1. 個別登録（ボタン・リンク・入力欄など）のルール
- 登録できるのはルール管理者のみ。登録・変更は、別の人の承認を受ける（SEC-1。必須になるのは第2段階。第1段階は兼務可で、記録に残す）
- 登録は、**接続先ごと**（テスト環境で登録したものは、本番の接続先では使えない。本番は、別に登録して承認する）
- 登録の結び付け先は、「接続先」「URLパターン」「要素の特定情報のハッシュ」
- 画面の記録の内容が変わったら、その要素の登録は無効になる。再登録が必要
- 実行時に、操作する要素の特徴（タグ、type、表示文字、フォームの送信先など）が登録時と一致することを確かめる。一致しなければ停止
- URLパターンは、パスまでの完全一致を基本とする。ワイルドカードは、ルール管理者が範囲を明記し、別の人が承認した場合のみ
- リンクは、click ではなく、リンク先のURLを読んで open_url で開く。onclick など、動作を持つ要素は、リンクとして登録できない
- 検索のように、問い合わせ文字列が付くURLは、パスの完全一致に加えて、許可する問い合わせ文字列の名前を明示する（14-7）
- 「副作用がない」ことの確認方法は、未定（未検証）。例：テスト環境で通信を記録し、状態を変える要求がないことを確かめる
- 「パスワード欄」「自動保存なしの画面」の登録も、同じルール（SEC-4）

### 7-2. 検出や判定の限界
- 検出・判定できる範囲は、接続先ごとに検証が必要（どこまでできるかは未確認）
- AIによる検出は補助とし、「取り消せない側に寄せる」ことにだけ使う

## 8. 実行計画の形式
- 構造化データ（JSON）で定義する。詳細は付録A
- 日本語の説明は、表示用の項目として別に持つ
- 承認の時点で版が固定される。承認後に直すと、新しい版になり、再承認が必要

### 8-1. 各手順が持つ項目
| 項目 | 内容 |
|---|---|
| 手順ID | 版をまたいで変わらない識別子。作成時に採番。シナリオの複製では、新しく採番 |
| 接続先 | 接続先の種類と、接続先の名前 |
| 操作の種類 | 付録A-2の一覧から選ぶ |
| 対象の指定 | 画面の記録の要素名 |
| データ項目 | 使う入力データの列 |
| 確認条件 | 操作後に確認する条件。必須。機械で判定できる形 |
| 照合ルール | 読み返し照合の比較ルール（正規化：全角／半角、日付書式、桁区切り、切り詰めなど）と、一致の基準 |
| 取り消し | 可／不可。**実行エンジンが操作許可リストから計算**（AIは決めない） |
| 根拠 | 元になったシナリオの文 |
| 表示用の説明 | AIが作る日本語の説明（参考）。承認画面の主な説明は、実行エンジンが計画から機械的に作る |

### 8-2. 構造
- 繰り返し（入力データの各行について）、条件分岐、確認ダイアログの扱いを、構文として持つ（付録A-3）
- 実行計画に書かれていない分岐、確認条件に合わない状態は、すべて「停止」

## 9. 安全面

### 9-1. 取り消せない操作の判定
- 操作許可リストにある操作だけを「取り消せる」とし、それ以外は「取り消せない」（既定）
- 利用者は、印を外せない。操作許可リスト・接続先許可リストの変更は、ルール管理者のみ。変更は、別の人の承認を受ける（SEC-1。必須になるのは第2段階で、第1段階は兼務の場合もその旨を記録に残す）。変更前後の内容は記録に残す（SEC-13）
- 許可リストが変わったら、承認済みの版は、再判定と再承認が必要（R5）
- 印の効果

| 印 | 効果 |
|---|---|
| 取り消せない操作 | ドライラン必須、承認画面で強調、直前の読み返し照合、状態を記録（10章）、件数の上限が必須（R9）、「AIが補った」値は1つずつ確認 |
| 接続先許可リストにない宛先 | 実行不可（許可リストの追加が先） |

- メール送信などの業務操作は、「取り消せない操作」として扱う

### 9-2. ドライランと、本番実行の条件
- ドライランは、取り消せない操作を実行しない。取り消せない操作の手前まで実行し、各行の終わりに、7章の手段で画面を初期状態へ戻して、次の行へ進む
- ドライランの合格基準：実行した全手順の確認条件が合格し、停止がないこと
- 取り消せない操作を含む版の**本番実行の条件**
  1. テスト環境で、ドライランが合格していること
  2. 最終承認が済んでいること（5章）
  3. 「未確定」が残っていないこと
  4. 初回は1件だけ実行して止まり、人が確認すること
- テスト環境がない接続先は、本番運用の対象外（将来の検討事項）
- ドライランの有効条件：**計画ハッシュ**、接続先の種類、接続先（スキーム・ホスト・ポート）、入力データの列定義が、本番実行と同じであること。1bに入った時点で、1a（スタブ）のドライランは、すべて無効とする。どれかが変わったら、無効。ドライランの記録と最終承認は、計画ハッシュとドライランIDに結び付ける
- 入力データの内容は、ドライランの結び付けに含めない。本番前に、R8の検査とプレビュー、件数の再入力で確認する
- ドライランは、テスト環境で行う。副作用の注意点（7章）に、実際に外へ出るものがあれば、テスト環境でも停止する

### 9-3. 読み返し照合
- 取り消せない操作の直前に、入力値を画面から読み返す
- 照合する項目は、手順ごとに実行計画で指定する（照合ルールは8-1）
- 比べる相手：入力データの値。AIが補った値や固定値は、実行計画に書かれた値
- 1項目でも一致しなければ、7章の手段で画面を元に戻して停止（戻せなければ「要確認」）。取り消せない操作は実行しない

### 9-4. 二重実行の防止
- 同じ版の二重起動を防ぐ（排他制御）
- 識別は、入力データで指定した**業務キー**で行う。実行計画や版をまたいで、重複を判定する
- 「成功」の業務キーは、別の版や、複製したシナリオからも、スキップする
- 対象システム側で既存の有無を照会できる接続先では、実行前に照会する。見つかったら、その行を「要確認」にして、実行を停止する
- 照会できない接続先では、「ローカルの記録だけが頼り」という制約を、承認画面に表示する
- 正当な再登録が必要な場合：承認者が理由を記録し、新しい業務キー（枝番を付けたもの）を付与する

## 10. 状態と再実行
状態は、「行（業務キー） × 取り消せない手順（手順ID）」の単位で持つ。

### 10-1. 状態
| 状態 | 意味 | 再実行での扱い |
|---|---|---|
| 成功 | 実行できたことを確認済み | スキップ |
| 失敗 | 取り消せない操作の**前**で止まったもの（実行されていないことが確実） | 対象 |
| 処理中 | 取り消せない操作の直前に書く | 自動で再実行しない |
| 要確認 | 「処理中」を書いた後の異常は、すべてこれ（結果が分からない、タイムアウト、緊急停止など） | 自動で再実行しない |

- 「処理中」の保存に失敗したら、取り消せない操作は実行しない
- 1行に取り消せない手順が複数ある場合：完了した手順は「成功」、止まった手順は「要確認」（または失敗）、それ以降の手順は未実行。再開は、止まった手順から（人の判定のあと）

### 10-2. 要確認・処理中の解消
- 人が対象システムで確認し、「実行済み」か「未実行」を記入する（判定者、時刻も記録）
- 「実行済み」→「成功」。「未実行」→「失敗」（再実行の対象）

### 10-3. 再開と版
- 同じシナリオ系列で、未解消の「処理中」「要確認」がある間は、起動しない
- 別のシナリオでも、同じ業務キーの未解消がある場合は、その行を止める（9-4）
- 修正後の新しい版で残りを続けるときは、再承認とドライランのやり直しが必要。「成功」の行は、新しい版でもスキップ（手順IDで照合）

## 12. 開発の進め方（AIバイブコーディング）
- 第1段階：6-1の範囲を作る。**接続できるのは、スタブ（偽の画面）、テスト環境、テスト用の公開サイト（14-7）のみ**（1aはスタブのみ。SEC-6の方法で、それ以外への接続を禁止する）
- 第2段階：API・ファイル書き込み、別の人の承認、1日ごとの上限、異常時の支援・修正案などを追加。本番の接続先は、13-3の条件を満たしてから。本番のテストは、取り消し手順が確認済みの少数のデータで
- 第3段階：ターミナル画面など、接続先の種類を増やす（7章を追加）
- 人が、生成されたコードを仕様と照らして確認する。仕様にない機能は足さない
- 実装の前提（ローカルのテスト用アプリ、技術スタック）は14章

### 12-1. 取り消せない操作を実行する関数（要件）
- 取り消せない操作は、実行エンジンの中の**1か所の関数**だけが実行する。接続先ごとの部品は、この関数を通さずに操作できない作りにする
- 関数の入力：版の識別子、手順ID、業務キー、画面から読み返した**生の値**（照合の結果ではなく、値そのもの）
- 関数が実行前に必ず確認すること
  - キルスイッチが発動していない（SEC-12）。通常停止のフラグが立っていない（14-3）
  - 版が承認済み（最終承認）で、計画ハッシュが承認時と同じ（SEC-2）
  - 有効なドライランが、この計画ハッシュに結び付いている（ドライランID。9-2）
  - 操作許可リスト・接続先許可リスト・個別登録の版が、承認時と同じ
  - 「未確定」が残っていない（9-2）
  - 確認条件が定義済み
  - 読み返した生の値と入力データの値を、関数の中で比べて一致する（9-3）
  - この業務キー・手順IDに、「成功」済みや、未解消の「処理中」「要確認」がない（9-4、10-3）
  - 上限内
  - 接続先が設定どおり
  - 初回1件の確認が済んでいる（初回のみ）
  - 最後に、「処理中」の保存が成功（ここより前の検査で拒否した場合、「処理中」は残らない）
- 1つでも満たさなければ、実行せず停止（理由をログに記録）
- 計画ハッシュの照合は、ドライランの開始時、実行の開始時、取り消せない操作の直前の3回行う。照合した計画は、メモリに1回だけ読み込み、その内容だけを実行する（照合と実行の間の差し替えを防ぐ）

## 13. セキュリティ要件
誤実行の防止（9章、12-1）に加えて、次を定める。方法が「未定」「未検証」のものは、そのまま残し、確定してから更新する。

### 13-1. 主な脅威と、対応する要件
| 守るもの | 主な脅威 | 対応する要件 |

## 14. 実装の前提（ローカルのテスト用アプリ）

### 14-1. 位置づけ
- 第1段階（1a、1b）は、担当者のPC上で動く、ローカルのテスト用アプリとして作る
- 起動先：http://localhost:8080（ポートは8080を既定とし、変更できる）
- ソースは、Gitで管理する
- 接続できるのは、スタブ、テスト環境、テスト用の公開サイト（14-7）のみ。本番の接続先には接続しない（SEC-6、13-3）。第2段階以降の配置（専用の実行環境）は、別に決める

### 14-2. 技術スタック
- 言語：PHP 8.5.12（以上の、8.5系の最新の修正版）
- フレームワーク：Laravel（確認時点の最新の安定版）
- ブラウザ操作：chrome-php/chrome。インストール済みのChromeを使い、起動時にChromeのバージョンを記録する。docs/TECH_STACK.md に記録した範囲外のバージョンなら、停止する（SEC-11のバージョン固定）
- 正確なバージョン、採用理由、未検証の事項は、**docs/TECH_STACK.md に記録する**
- フレームワーク・ライブラリを追加・更新するときは、公式情報で最新の安定版を確認し、docs/TECH_STACK.md を更新する（必須）
- 画面は、Laravel標準のBladeと少量のJavaScript。外部のJavaScriptライブラリは、必要になるまで入れない

### 14-3. 構成の方針

#### 配置と依存の向き
| 場所 | 入るもの |
|---|---|
| src/Plan | 実行計画の型、検査、計画ハッシュ |
| src/Guard | 12-1の関数、許可オブジェクト |
| src/Policy | 接続してよいホストの上限（定数）。操作許可リスト、接続先許可リスト、個別登録は、src/Stateの追記のみの記録で管理する（版、承認、変更前後） |
| src/State | 状態、記録、チェーン、停止フラグ（PDOで保存） |
| src/Browser | ブラウザ操作のインターフェースと実装（1a：Chromeを使わない偽の部品、1b：chrome-php用） |
| src/Ai | AIクライアントのインターフェース、AIの出力の形式検査 |
| src/Runner | ワーカーが使う、実行の流れ |
| app/Http | 画面のコントローラ、ミドルウェア（Host・Origin・トークンの検査） |
| app/Console | Artisanコマンド（ワーカー、起動） |
| resources/views | 画面（Blade） |

- src/ は、フレームワークに依存しない素のPHPで書く。**src/ に Illuminate を書かない**。依存の向きは、app → src の一方向のみ
- 保存は、src/State の中で、PDOを直接使う（Eloquentは使わない）
- AIの出力の検査は、src/Ai に置く
- 上記は、テストで機械的に確認する（src/ 内にIlluminateが出現しないこと。HeadlessChromiumを使うのは src/Browser の中だけであること）
- 理由：安全に関わる中心部分の依存を減らし（SEC-11）、フレームワークなしでもテストできるようにするため

#### 12-1の強制
- 取り消せない操作のメソッドは、12-1の関数だけが作れる「許可オブジェクト」（privateコンストラクタ）を引数に取る。PHPの言語機能だけでは、完全には強制できないため、迂回を試すテストを用意する（SEC-11）。取り消せない操作のメソッドの中でも、計画ハッシュ・手順ID・業務キーを、保存先と照合し直す（多重の防御）

#### 実行の流れ
1. 画面（app）は、プレビューの表示、件数の入力、承認、「実行要求」の受け付けだけを行い、保存先に記録する（POST、CSRF必須）。実行そのものは行わない
2. ワーカー（Artisanコマンド、別プロセス）が、実行要求の**IDだけ**を受け取り、保存先から内容を読み、12-1の検査をすべて src/ で行ってから実行する
3. 画面から、シェルのコマンドを組み立てて起動しない。ワーカーは、担当者がコンソールで起動する
4. 停止：画面の停止は、停止フラグを保存先に書く（協調停止）。ワーカーは、各手順の前と、12-1の直前で読む。ブラウザの待ちの間は読めない。緊急停止は、コンソールの専用コマンドで、記録したプロセスIDのワーカーとChromeをまとめて終了する（方法は、実行PCのOSごとに決める。11章）
5. 異常終了のあと、次の起動時に、「処理中」を「要確認」に変え、残った実行用プロファイルを破棄する
6. 二重起動の防止：ファイルロックと、保存先の一意制約
7. 保存：SQLite。WALモード、busy_timeoutを設定し、記録のチェーンへの追記は、BEGIN IMMEDIATEを明示的に実行して直列にする（PDOのbeginTransaction()の既定では、そうならない見込み。要確認）
8. CLIから承認を作れない。作る場合も、12-1で同じ検査を通る

### 14-4. フォルダ構成（案）
```
nl-rpa/
├ docs/              仕様書、TECH_STACK.md
├ src/               中心部分（素のPHP）
│  ├ Plan/ Guard/ Policy/ State/ Browser/ Ai/ Runner/
```

- データ（ログ、結果、記録、画面の記録、入力データ、認証情報）は、リポジトリの**外**の専用フォルダに置く（環境変数 NL_RPA_DATA_DIR で指定）
- Laravelの既定のログ、セッション、DBの置き場所は、NL_RPA_DATA_DIR に向ける。APP_DEBUG=false。npm関連の雛形は使わない。**既定値は未確認**のため、1aの最初の作業で確認する
- スタブは、アプリとは別のポート（例：8081。設定で変更可）で配信する。Chromeでこれを開くのは1bから（1aは、偽のブラウザ部品が、stubs/の内容を直接読む）。アプリ自身（localhost:8080）は、接続先許可リストに入れない（自動操作のブラウザが、管理画面を操作できないようにするため）

### 14-6. 動作確認の範囲と、1aの最初の作業、1bに入る条件

#### 1aの最初の作業（実装の前に確定する）
- 計画ハッシュの正規化の方式（提案：RFC 8785のJSON正規化と、SHA-256。RFCのテスト用データで実装を確かめる）
- 付録Aの全項目
- 実行PCのOS（11章）
- テストの部品（PHPUnit、Pest）
- Laravelの既定の確認（14-4）
- コミット時の秘密情報の検出ツールの選定
- AIのスタブ（固定の実行計画のJSONを返す）。AIクライアントは、インターフェースの裏に置く
- **通信遮断の事前検証**（スタック全体の成否を決めるため、前倒しする）：ローカルのスタブを相手に、次の2種類を分けて確認する。結果は、docs/TECH_STACK.md に記録する
  - 遷移の検査（SEC-5）：リダイレクト、window.open、target=_blank、iframe、meta refresh、JavaScriptによる遷移が、停止または遮断されること
  - 遷移以外の外部通信（SEC-6のネットワーク側で遮断）：fetch/XHR、WebSocket、sendBeacon、フォームの外部送信、ダウンロード、Service Workerが、遮断されること

#### 1aの動作確認
- 偽のブラウザ部品（Chromeなし）で、骨組みの動作を、単体テスト（tests/Unit）と結合テスト（tests/Feature）で確認する
- 1aの間だけ、スタブでのドライラン合格を、9-2の「テスト環境でのドライラン合格」とみなす。1bに入った時点で無効（9-2）
- 動作確認は、PHP 8.5.12以上の8.5系の環境で行う。この確認が済むまで、完成とは扱わない

#### 1bに入る追加条件
- 専用のOSアカウント（SEC-10）と、ネットワーク側の制限（SEC-6）が、動いていること
- 1aの通信遮断の事前検証が、chrome-php/chromeの実機で、すべて合格していること
- **使い捨てプロファイルの検証**：終了時に破棄されること。SEC-3の無効化（パスワードの保存、拡張機能、テレメトリ）が、起動オプションで実現できること。会社のポリシーで強制される拡張機能が残らないか、chrome://policy で確認する（未確認）
- **デバッグ接続の検証**：Chromeのリモートデバッグ用の接続を、他のOSアカウント・他のプロセスから使えないこと（chrome-php/chromeがポートを開かない方式に対応するかは、未確認）
- **緊急停止の検証**：ワーカーがブラウザの待ちで止まっている間も、緊急停止でワーカーとChromeの子プロセスが残らず終了すること
- SEC-4のパスワード欄の、フレームの照合
- Chromeのバージョンの固定のしやすさ（Chrome for Testingの採用）を、検討する
- 不合格の場合の代替：「ネットワーク側のプロキシで強制する」または「別の部品（Node.jsのPlaywrightなど）に切り替える」のどちらかを、ルール管理者と仕様の責任者が、1bに入る前に判断する。切り替える場合は、14-2とTECH_STACK.mdを更新する

### 14-7. テスト用の公開サイト（例：Yahoo! JAPANの検索）
- 対象：www.yahoo.co.jp、search.yahoo.co.jp（例。ビルド時の定数に載せるのは、1bの通信検査テストが合格してから）
- 入力は、ダミーの検索語だけ。計画に書いた固定値のみで、入力データの列は使えない（SEC-8。実行エンジンが強制する）
- この例外は、第1段階だけ
- SEC-8（社外への入力は取り消せない扱い）の例外とする。個別登録（7-1-1）するのは、検索ボックスと検索ボタンだけ
- 問い合わせ文字列は、許可する名前を明示する。許可するフレームも、実測して決める（広告などで外部のフレームが開くと、停止になる見込み。未確認）
- 利用規約とrobots.txtで、自動アクセスが許されるかを、使う前に確認する（どちらも未確認）。確認がとれなければ、自前のスタブで代替する
- 検索ボックスへの入力で、候補表示のための外部通信が起きる可能性がある（未確認）。通信を記録して確かめる

## 付録A 実行計画の形式（骨子）

### A-1. 全体の骨子（JSON）
```json
{
  "plan_id": "PLN-0001",
  "version": 3,
  "plan_hash": "（実行エンジンが計算する。この欄は、計算に含めない）",
  "scenario_id": "SCN-0007",
  "created_by_ai": { "model": "（記録）", "prompt_version": "（記録）" },
  "allowlist_versions": { "operations": 5, "destinations": 2 },
  "screen_record_version": 4,
  "input": {
    "columns": [
      { "name": "商品コード", "type": "text", "required": true, "max_bytes": 12 },
      { "name": "数量", "type": "number", "required": true, "role": "quantity" },
      { "name": "納品日", "type": "date", "required": true, "format": "YYYY-MM-DD" },
      { "name": "伝票番号", "type": "text", "required": true, "role": "business_key" }
    ]
  },
  "limits": { "max_rows_per_run": 100, "max_quantity_per_run": 5000 },
  "steps": [
    { "id": "S-001", "action": "open_url", "target": "login_page",
      "verify": { "type": "text_visible", "value": "ログイン" },
      "reversible": true, "source": "「発注管理システムにログインする」",
      "label": "ログイン画面を開く" }
  ]
}
```
（上は骨子。全項目の定義は、第1段階の実装前に確定する）

### A-2. ブラウザの操作の種類（取り消し可否つき）
| 操作 | 内容 | 取り消し |
|---|---|---|
| open_url | 登録されたURLパターンの画面を開く | 可 |
| read_text | 要素の文字・値を読む | 可 |
| type_text | 入力欄に入力（自動保存なしの画面のみ）。キー操作は送らない（改行・タブは入力しない） | 可 |
| clear_text | 入力欄を空にする | 可 |
| click | ボタンのクリック（リンクには使わない。7-1-1） | 個別に登録されたボタンは可、それ以外は**不可** |
| press_key | キー操作（Enterなど） | **不可** |
| login | 認証情報の入力（SEC-4）。パスワード欄は、ルール管理者が登録した要素（type=password）だけ。失敗は1回で停止（R20） | 可（業務データを変えない。最終ログイン時刻の更新などはあり得る） |
| confirm_dialog | 確認ダイアログのOK | **不可** |
| wait_for | 条件が出るまで待つ（上限あり） | 可 |
| write_result | 結果に値を記録 | 可（結果の記録先は実行エンジン内） |

### A-3. 構文
- for_each_row：入力データの各行について、以下の手順を繰り返す
- if / else：確認条件による分岐。else がなければ、停止
- on_dialog：想定する確認ダイアログと、その対処（OKする／停止）。書かれていないダイアログは、停止

### A-4. 確認条件・照合ルール・列定義
- 確認条件の種類：text_visible、text_equals、element_exists、url_matches、value_matches（照合ルールつき）
- 照合ルールの正規化：width（全角／半角）、date_format、thousand_separator、trim、max_length
- 入力データの列定義：name、type（text／number／date）、required、max_bytes、role（business_key／quantity／amount／personal_info）
