# 自然言語RPA（ローカルのテスト用アプリ）

業務の手順を日本語で書いて、RPAとして動かすためのアプリです。仕様は [docs/nl_rpa_spec_v1.7.md](docs/nl_rpa_spec_v1.7.md)、技術スタックは [docs/TECH_STACK.md](docs/TECH_STACK.md)、実装で決めたことは [docs/付録A_確定.md](docs/付録A_確定.md) にあります。

**いまは第1段階の「1a」です（ただし、完成とは言えません）。** 接続できるのは、スタブ（偽の画面）だけです。AIは、固定の計画を返すスタブです。本番の接続先には、接続できません。仕様14-6では、PHP 8.5.12 以上で、全テストが通ったときに、完成とします。まだ、確認できていません（下の「注意」）。

「1b」（テスト環境への接続）には、まだ入っていません。入る条件（専用のOSアカウント、ネットワーク側の制限など）が、満たせていないためです。下の「本物のChromeで動かす」は、1bの**事前の検証用**です。

## ローカルでは満たせない安全の条件（LOC-8）

この画面とワーカーは、あなたのPC上で、同じOSアカウントで動きます。次の条件は、満たせません。

**1aで、満たせないもの**

- **SEC-2（記録の保護）**：記録（承認、状態、ログ）の保存先を、実行者から書き換えられない場所に置くこと。記録のチェーンは、実行の前に検証します（`Ledger::verify()`）が、「部分的な改ざんのみ検知できる（未検証）」です。末尾の記録を消されても、見つけられません。
- **SEC-10（専用のOSアカウント）**：この画面とワーカーは、あなたのOSアカウントで動きます。

**1bに入る条件（いまは、満たせていません）**

- 専用のOSアカウントで動かすこと（SEC-10）
- ネットワーク側の通信制限（SEC-6）。いまの通信の制限は、Chrome自身の設定（起動オプション）だけです

## 準備

必要なもの：PHP（拡張：`pdo_sqlite`、`mbstring`、`intl`、`posix`）、Composer。

```bash
composer install
cp .env.example .env
php artisan key:generate
```

`.env` の `NL_RPA_DATA_DIR` に、**リポジトリの外**の、絶対パスを書きます。ログ、セッション、記録、入力データ、アクセストークンのハッシュが、ここに入ります。未設定、または、リポジトリの中を指していると、画面は起動しません。

`APP_DEBUG=false` のままにしてください（`true` だと、起動しません）。

## 起動

```bash
php artisan nlrpa:serve
```

`http://localhost:8080` を開いて、コンソールに表示された**アクセストークン**を入力します。再起動すると、トークンは変わります。127.0.0.1 だけで待ち受けます。止めるときは、Ctrl+C を押します。

起動コマンドは、`php -S` を直接起動し、次の設定を `-d` で渡します（php.ini を直す必要は、ありません）。要求を処理するPHPの設定は、毎回、確かめます。

- `session.upload_progress.enabled=0`（php.netの告知による。LOC-7）
- `display_errors=0`、`expose_php=0`

`php -S` は開発用のサーバーです。ローカルのテスト用途に限ります。`public/` の中の静的ファイル（`nlrpa.css`）は、`php -S` が直接返すため、Hostの検査やセキュリティヘッダが付きません。`public/` に、秘密を置かないでください。

## 本物のChromeで動かす（1bの事前の検証用。接続先は、スタブの画面だけ）

既定は、Chromeを使わない偽の部品です（`NL_RPA_BROWSER=fake`）。本物のChromeで動かすには、`.env` に、次を書きます。

```ini
NL_RPA_BROWSER=chrome
NL_RPA_CHROME=/path/to/chrome        # 未指定なら、自動検出
NL_RPA_CHROME_NO_SANDBOX=false       # rootで動かす環境（コンテナなど）のときだけ true
NL_RPA_CHROME_MAJOR=153              # 許可するメジャーバージョン（カンマ区切り）。必須（未指定だと起動しない）。検証したのは、153（Linux）
NL_RPA_STUB_PORT=8081                # スタブの画面のポート。8081、または18300〜18399だけ（SEC-6。それ以外は起動しない）
```

スタブの発注画面（Web版）を、別のコンソールで起動します。

```bash
php artisan nlrpa:stub-web
```

あとは、「使い方」と同じです。Chromeは、起動オプションと、エンジンの検査で、許可した接続先（スタブの画面）以外へ通信しないようにしています。ただし、これは、Chrome自身の設定による制限です。ネットワーク側の制限ではありません。UDPの一部やQUICは、未検証です（`docs/TECH_STACK.md` 7-5）。接続を許すポートは、設定（`NL_RPA_STUB_PORT`）で変わります。実行のたびに、使い捨てのプロファイルで起動し、終了時に破棄します。

- **切り替えの注意**：`fake` と `chrome` を切り替えると、もう一方のドライランは、無効になります（仕様9-2）。計画の承認は、そのまま使えますが、ドライランと最終承認は、やり直しです（最終承認は、ドライランに結び付いているため、古い最終承認では、登録も実行もできません）
- 実行の画面に、スタブ側に記録された発注が出ます。行ごとの状態と、見比べられます
- **ローカルでは、満たせない条件があります**：同じPCの、他のプロセスや、他のOSアカウントから、Chromeのデバッグ用のポートへ接続できます（chrome-php の制約）。詳しくは、`docs/TECH_STACK.md` の7章を見てください。ネットワーク側の制限（プロキシ、ファイアウォール）は、未実施です

## 使い方

**初回の1件**は、その実行で、最初に実行した行です。前の実行で成功した行は、数えません。
**要確認**の行は、画面で「実行済み」か「未実行」を判定します（「処理中」は判定できません）。

1. 画面で、シナリオを書いて「実行計画を作る」を押す
2. 計画を確認して、承認する（AIが補った取り消せない手順は、1つずつ確認する）
3. 「ドライランの要求を作る」を押す → コンソールで、ワーカーを動かす
4. ドライランの結果を見て、最終承認する
5. 入力データ（CSV）を取り込み、プレビューで件数を入力して、実行を登録する
6. 「実行の要求を作る」を押す → ワーカーを動かす。**初回は1件だけ実行して止まります**
7. 結果を確認して、「初回の1件を確認した」を押す → もう一度、要求を作ってワーカーを動かす

ワーカーは、画面からは起動しません。コンソールで、要求の番号を指定して動かします。

```bash
php artisan nlrpa:worker 1
```

## コマンド

| コマンド | 内容 |
|---|---|
| `php artisan nlrpa:serve` | 起動（トークンの発行と表示） |
| `php artisan nlrpa:worker {要求の番号}` | 要求を1件処理する |
| `php artisan nlrpa:emergency-stop` | 緊急停止。キルスイッチを立て、記録したワーカーと子孫のプロセスを終了する（Linuxのみ。PIDと開始時刻が一致するものだけ） |
| `php artisan nlrpa:kill-switch off` | キルスイッチの解除 |
| `php artisan nlrpa:stub-web` | スタブの発注画面（Web版）を起動する（本物のChrome用。別のコンソールで） |
| `php artisan nlrpa:recover` | 異常終了のあとの後始末（処理中→要確認、残ったChromeとプロファイルの回収）。「処理中」の行は、これを実行してから、画面で判定する。動いているワーカーのものには、触らない。孤児のChromeが実行のロックを持っていても、先に回収するので、止まらない |

画面では、次のことができます。
- 計画の確認：手順（実行エンジンが機械的に作った説明）、入力データの列と業務キーの列、**前の計画との差分**（重要な変更を強調）
- ドライラン・実行の結果：**手順ごとの確認条件の合否**、行ごとの状態、画面から読んだ値（発注番号など）、**結果のCSVのダウンロード**

画面の「停止」ボタンは、停止の旗を立てるだけです（実行中の手順が終わった時点で止まります）。すぐに止めたいときは、緊急停止を使ってください。

## 秘密情報の検査

```bash
php tools/scan-secrets.php
```

gitで管理しているファイルに、鍵やトークンらしい文字列がないかを調べます（暫定の簡易版。専用ツールは未選定）。テストにも、含まれています。コミットのたびに、自動では動きません。

## テスト

```bash
php artisan test
```

## 注意

- 顧客名や単価などの機密を、シナリオに書かないでください
- 動作確認は、PHP 8.5.12 以上の 8.5 系で行う決まりです（仕様14-6）。**この環境では、8.3.6 でしか確認できていません**
- 完成の確認（8.5.12 での全テストの合格）は、`NL_RPA_REQUIRE_FULL_TESTS=1 php artisan test` で行ってください。この設定のときは、Chrome や Linux がなくて飛ばされるはずのテストが、飛ばされず、失敗になります（安全のテストが、黙って飛ばされるのを防ぐため）
- 成功済みの判定は、AIが振る手順IDではなく、接続先・操作・対象から、エンジンが計算した識別子で行います。版が変わって手順IDが変わっても、成功済みの業務キーは、もう一度、実行されません（仕様9-4）
- 未解消の「処理中」「要確認」が残っている間は、本番の実行を始められません（仕様10-3）。先に、画面で判定してください
